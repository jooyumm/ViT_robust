# P16 PatchFool 정확도 상승 원인 (2026-11-02)

주원인은 픽셀 범위 제약 변경이다. 과거 공격은 `clip_valid_range=False`였고,
새 00 전체 재실행은 `True`였다. 이것을 같은 공격 조건의 재실행으로 설명한 것이 잘못이었다.

## 동일 입력에서 원인 분리

ImageNet seed=42의 동일 64장, 동일 P16 checkpoint, batch=64, 250회, 같은 초기 seed를 사용했다.
과거 구현은 git `7393b5b`의 `src/attacks/patch_fool.py`에서 복원했다.

| 설정 | 정답/64 | 공격 후 정확도 | 공격 이미지의 픽셀 공간 범위 |
|---|---:|---:|---|
| 과거 코드, 픽셀 제한 없음 | 4 | 6.25% | −17.78 ~ 16.81 |
| 같은 과거 코드, 픽셀 제한만 켬 | 22 | 34.38% | 0 ~ 1 |
| 현재 코드·현재 기본값 | 23 | 35.94% | 0 ~ 1 |

과거 코드에 clipping만 적용한 실험을 별도 GPU에서 반복해도 22/64였다.
원본 clean 정답은 57/64이며 세 조건의 모델 지문·이미지 ID가 일치함을 검증했다.
이전/현재 코드의 모델 이름과 전처리는 동일하다. 960→1000장 변경만으로는 약 26%p의 상승을
설명할 수 없다(추가 40장이 모두 정답이어도 증가 폭은 약 4%p 이내).

`−17.78~16.81`은 mean/std=.5 정규화를 해제한 실제 RGB 픽셀 공간 값이다.
일반 이미지의 유효 범위 0~1을 벗어나며, 현재 공격은 그 범위 안에서만 최적화한다.
따라서 과거 RA 약 6%와 현재 RA 약 32%는 서로 다른 위협 모델의 결과다.

다른 변경은 CLS→incoming 위치 선택, delta→replacement 초기화, PCGrad의 norm→norm²다.
이 64장 검증에서는 clipping만으로 대부분의 상승이 재현됐지만, 각 변경의 전체 1000장 기여도나
상호작용을 수치로 분해했다고 주장하지 않는다. 현재 조건과 과거 조건에서 동일한 attack RNG를
명시적으로 재설정한 원인 분리 실험이며, 과거 실행 전체의 RNG 궤적까지 복원한 것은 아니다.

## 연구 해석

P8이 항상 강건하다는 결론으로 이어지지는 않는다. 과거 unbounded 결과와 현재 valid-range
결과를 분리해야 한다. 유효 픽셀 범위에서 같은 공격 면적을 맞췄을 때 P8의 이점이 유지되는지는
현재의 별도 비교 결과로 판단한다. 과거 결과에 맞추려고 clipping을 끄거나 숫자를 고치지 않는다.

## 자료 정리

원인 분석의 비교 조건과 핵심 수치는 위 본문에 남겼다. 사용자의 실행 이력 정리 요청에 따라 `00_patch_size_tradeoff/results/audits/`의 임시 실행본·과거 코드 복사본은 삭제했다. 현재 실험의 최종 지표와 그래프는 00의 `results/metrics/`, `results/figs/`에 유지한다.
