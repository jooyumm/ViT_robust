# 평가 조건·구조 점검 (2026-10-29)

2026-11-02 추가 확인: P16 정확도 상승은 같은 64장에서 clipping만 켜 6.25%→34.38%로 재현했다. 과거/현재 결과의 위협 모델이 달랐다. [원인 분리 검증](patchfool_accuracy_shift.md)을 참고한다.

## 먼저 확인된 결론

현재 03의 42.2% 공격 실패율 자체가 attention 추출 오류의 증거는 아니다. 고정 500장 중 clean 정답은 419장이고, 공격 성공 242장·실패 177장·clean부터 오답 81장이다. 공식 timm 추출기로 재추론해도 예측 변화는 없었다. 다만 이 공격이 충분히 강한지, 다른 논문과 동일 조건인지는 별도 문제다.

## 논문과 다른 조건

| 항목 | ViTGuard | ARMRO | 현재 실험 및 해석 |
|---|---|---|---|
| 탐지 평가 표본 | 성공한 공격: clean 정답→공격 오답 | 공격 이미지에 대한 분류 및 패치 위치 탐지 평가 | 전체 500장 TPR/AUROC와 성공 공격 242장 TPR/AUROC를 각각 보고한다. 위치 정확도와 공격 존재 탐지도 구분한다. |
| 데이터·모델 | CIFAR-10/100·Tiny-ImageNet, 사전학습 ViT의 head를 downstream에 맞게 fine-tune | ImageNet, 여러 ViT/DeiT·입력 해상도 | ImageNet 224, timm AugReg ViT-B. 이름이 ViT라고 체크포인트까지 같은 것은 아니다. |
| P16 공격 면적 | 4개 토큰 | 1·2·5개 토큰 | 03은 1개 토큰: 256/50176≈0.51%. 4개는 약 2.04%. 수치를 바로 비교하면 안 된다. |
| 학습·보정 | MAE 학습과 탐지 설정 선택 사용 | 모델별 100장으로 threshold 선택 | 실행 시 학습·보정 없음. 같은 데이터에서 반복 탐색한 것까지 독립 검증이 되는 것은 아니다. |
| 공격 예산 | 공격별 부록 설정 | 픽셀 perturbation radius 0.8 | 유효 범위 내 패치 교체와 L∞ 반경 제한은 서로 다른 제약이다. 정규화 단위까지 맞춰야 한다. |

출처: [ViTGuard §3, §5.1.2–5.1.3](https://arxiv.org/html/2409.13828v1), [ARMRO §6–7 및 부록](https://proceedings.mlr.press/v202/liu23n/liu23n.pdf). ARMRO의 false-positive 그림은 정상 **토큰**을 잘못 선택하는 의미도 포함한다. 우리 이미지 단위 FPR와 분모가 같다고 해석하지 않는다. ARMRO가 성공 공격만 선별했다고 확인한 것은 아니다.

ViTGuard에는 MAE 학습과 downstream head 학습이 있으므로, 이를 그대로 가져오면 현재의 학습 불가능 조건과 달라진다. 우리 no-training 주장은 추론 시 추가 학습/보정을 하지 않는다는 범위다. 별도의 사전학습 자체가 없는 모델이라는 뜻이 아니다.

## 현재 코드·실험에서 놓친 부분

1. **분모 혼용:** 이전 `attack_detection_rate`와 `detector_auroc`는 실패한 공격과 clean 오답을 포함한 전체 공격본 기준이었다. 성공 공격만 보는 논문과 바로 비교할 수 없었다. 전체/성공/실패/clean 오답 집단의 탐지율을 구분했다.
2. **00 표본 수 절삭:** `num_samples // batch_size`로 실제 표본 수를 줄였다. 예컨대 1000장·batch=64는 960장이었다. 마지막 작은 batch를 유지하도록 수정했다. 과거 로그의 960장을 1000장으로 소급 해석하지 않는다.
3. **과거 공격 설정 추적:** 예전 manifest에는 모든 함수 기본값이 펼쳐져 있지 않고 `pf_clip_valid=True`와 unbounded라는 limitations 문구가 충돌하기도 한다. 과거 문구를 임의 수정하지 않는다. 신규 실행은 `patch_fool_config`로 실제 옵션을 명시하고 소스·데이터 지문을 기록한다.
4. **공식 재현 범위:** 로컬 PatchFool은 timm 체크포인트, norm² PCGrad, Contiguous/고정 sparse 확장이 포함된다. 다중 패치의 attention 목적함수는 첫 선택 token을 target으로 한다. 면적을 맞췄다고 공식 multi-patch 실험 전체와 같아지는 것은 아니다. [공식 main.py](https://github.com/GATECH-EIC/Patch-Fool/blob/main/main.py)
5. **공격 강도 검증 부재:** 현재는 단일 초기화·최종 iterate다. 실패한 표본이 여러 위치/초기화 및 더 강한 최적화에도 안전하다고 확인한 것은 아니다. 강도 검증은 별도 ablation으로 수행하고 기존 03 관찰 데이터는 유지한다.
6. **적응형 공격 부재:** 방어가 없는 모델을 공격하고 그 결과를 방어하는 평가다. 방어 경로까지 최적화한 결과가 아니다. randomized v2도 무작위성만으로 안전성을 보장하지 않는다. EOT를 고려한 별도 평가가 필요하다.
7. **checkpoint 혼입:** P8/P16은 별도 가중치다. 서로 직접 공격한 정확도 차이를 patch 크기 하나의 인과 효과로 단정할 수 없다.
8. **탐지기의 성격:** 현재 탐지기는 TV + attention 고정 heuristic이다. 03의 attention 흐름 관찰이 탐지 효과를 입증하지는 않는다. 임계값·TV·attention·사분면 집계의 기여는 분리 ablation이 필요하다. 대표 패치를 먼저 정한 뒤 eligibility를 적용하는 규칙은 유지했으며, 다른 후보가 무시될 수 있는 설계상 한계가 있다.
9. **그림·위치 해석:** 03 summary는 각 집단의 첫 표본 예시이고, heatmap은 성공/실패를 섞은 평균이다. 대표 예시만으로 일반화하거나 인과를 말하지 않는다. 사분면을 정확히 골랐다는 것과 공격 픽셀을 정밀 분할했다는 것도 다르다.
10. **실행 비용:** `elapsed_seconds`는 모델 로드·검사·파일 I/O까지 포함한다. 추론 latency가 아니다. latency는 같은 장비/배치에서 warm-up, CUDA 동기화, 반복 측정을 별도로 해야 한다.

## 이번에 정리한 구조

- `src/cohort.py` + `data/gt/imagenet500.json`: 01/02의 공통 500장 ID·경로·모델 계약. 02가 01의 Python 패키지를 import하지 않는다. 원본·공격본·GT·어텐션은 루트 data의 clean/attacks/gt/attention에 역할별로 두며 기존 정밀 데이터는 유지한다.
- `src/provenance.py`: 파일 SHA256·모델 state_dict 지문 한 구현.
- `src/patches.py`: 공유 패치→사분면 좌표·실제 변경 coverage. GT 그림용 한 장 adapter는 01/ground_truth에 둔다.
- `02_detection_defense/defense_common/`: 두 방어의 혼합 평가·지표 분모·3조건 그림. 프로젝트 바깥 src로 끌어올리지 않는다.
- `region_switch/experiments/model_support.py`: P8/P16 비교에만 쓰는 source 검증·재사용·그림. Clean→Attacked→Defended 순서를 유지한다.
- 변환 알고리즘은 `region_switch/core/switch.py`, 무작위 변환은 `region_switch_v2/randomize.py`, 03 집계는 03 폴더에 유지한다.
- 두 `data_io.py`와 01의 `samples.py`는 공통 모듈로 대체했다. 무의미한 capture.close()와 사용되지 않는 attention loader도 제거했다.
- 모호한 `from run/attention/switch/data_io`를 패키지 import로 바꿨다. /tmp에서 실행해도 CLI import가 되도록 했다.
- TV global MAD의 동일 계산 196회를 1회로 줄였고, AUROC의 N×N 임시 배열을 정렬 기반 계산으로 바꿨다. 수식과 threshold는 유지한다.

이는 새 P16 직접 공격에서 얻은 30.2%/76.0%나 P8 조건의 수치와 다른 실행이다. 서로 섞지 않는다. 성공 공격 집단만의 지표를 추가했다고 임계값을 다시 고른 것은 아니다.

검증: 단위·회귀 검사 27개 통과, 저장된 500쌍 재평가 및 데이터 감사 통과, 10개 CLI를 저장소 밖(`/tmp`, PYTHONPATH 없음)에서 확인했다.

실제 clean/공격 입력에서 변경 전후 logits·attention·탐지 출력 전체가 일치했다. P16 가중치 지문은 유지됐고 고정 변환 및 v2의 고정 경계 동치성도 확인했다. 기존 PNG·archive 내용·과거 reruns 소스는 수정하지 않았다. 데이터 이동에 맞춰 과거 스냅샷의 데이터 symlink 대상만 갱신했다.
